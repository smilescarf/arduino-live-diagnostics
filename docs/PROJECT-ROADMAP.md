# 项目建议与下一步顺序

这个项目适合定位为“Arduino IDE 内的中文实时诊断与实验助手”。编辑时发现问题、理解 API、从课程实验开始，形成一个连续的学习过程。短期先把 ESP32-S3 做扎实，再增加板型。

## 1. 优先稳定诊断（下一个版本）

- 保留编译器原始诊断、错误码和相关位置，中文解释独立维护；只在有明确证据时移动红线或提供修复。
- 把已遇到的缺分号、错误 for、缺 if 条件、中文符号以及多 .ino/头文件/库依赖加入回归样例，验证未保存增量修改、行列位置和错误清除。
- 区分“准备编译配置”“索引中”“已收到诊断”“超时/失败”，超时给出重试入口；不要以转圈替代故障信息。
- 公开核心/工具链/宿主版本矩阵，先承诺已验证组合。静态诊断不能检查接反、电压、接触不良或真实外设行为。

## 2. 把模板做成可维护的课程数据

- 本版已统一模板 ID、课次、来源页、板型、依赖、接线、参数和预期现象。之后将器件参数和代码生成分离，加入引脚选择与冲突检查，再考虑可视化接线。
- 先选择板型和器件，再填少量参数：GPIO、有效电平、灯珠数量、显示驱动和尺寸。不要根据课件标题推测真实模块。
- 增加“最小实验 → 改一个参数 → 综合挑战”的练习顺序；允许只生成骨架/提示，避免初学者只复制答案。
- 库函数继续优先读取当前实际安装库的头文件和 examples。中文注释可由人工整理的知识库增强，不能把扫描到的声明都当作可直接调用的全局函数。

## 3. 用编译矩阵守住模板质量

- 固定验证核心和依赖版本，变更模板时编译所有受支持板型；出现 API 变更先修复模板或明确限制版本。
- 本版有独立模板编译脚本和 examples 生成脚本，模板列表与仓库示例来自同一份数据，避免两份代码逐渐不一致。
- 下一步增加 Linux/Windows 的 CI 编译任务，缓存核心和库；把硬件实测另外记录，包括具体板卡、模块、接线和观察结果。
- 优先实测中断消抖、舵机电源/限位、超声波超时、显示扫描重影、双板 ESP-NOW、BLE 配对/断线重连。

## 4. 再发布 GitHub 公开测试版

- 首先发布清楚标为 alpha 的版本，提供一分钟使用说明、真实操作截图、版本兼容表和故障反馈模板；功能说明与验证证据一致。
- 原课件保留本地，仓库提供独立实现的代码、课件名称和页码映射；PPTX 不打进 VSIX，减小下载体积。公开课件原件需确认允许发布。
- 增加贡献模板的清单：来源、器件、板型、依赖、预期现象、编译结果和实测结果。
- 网络示例不包含真实密码，基础网页控灯只用于可信局域网。进入远程控制阶段再加入鉴权、超时关闭和重连策略。

建议发布节奏：诊断稳定性 → 参数化模板与实测 → GitHub alpha → 跨板型兼容。课程数量可以逐步扩展，诊断位置和“下一步怎么做”应始终清楚。

## 参考实现与版本依据

- [Espressif 官方 2.x → 3.0 迁移说明](https://docs.espressif.com/projects/arduino-esp32/en/latest/migration_guides/2.x_to_3.0.html)：LEDC、定时器和 BLE 的 API 存在破坏性变更，因此模板需要明确核心版本，不能混用旧教程签名。
- [Arduino 官方 compile-sketches](https://github.com/arduino/compile-sketches)：可作为后续 GitHub Actions 模板编译与结果报告的参考。本版已经在本机通过 Arduino CLI 验证，尚未执行云端硬件实验。
